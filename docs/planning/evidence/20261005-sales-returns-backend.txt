T18 bounded sales returns backend — implementation evidence draft
Date: 2026-10-05

Scope implemented in task-owned files
- Exact T16 handover-allocation return eligibility; requested, approved and
  credited claims consume capacity while rejected claims release it.
- Immutable return claim with returner identity/contact and declared condition.
- Existing ManagerCase request/review/consume lifecycle; self-review and stale
  binding rules remain those of the shared engine.
- Fingerprinted processing options over claim review, exact balances, valuation
  heads, original invoice prices/tax and debt-first value allocation.
- Exact original-balance RETURN movement into quarantine; reservations do not
  reopen and serial/cross-store returns fail closed.
- Cumulative proportional restoration of the original HANDOVER ISSUE value into
  the current cost-pool head, including exact final residual conservation.
- Immutable SCR credit note and lines; outstanding invoice debt is reduced first,
  then surplus creates an append-only non-expiring customer-credit liability.
- A physically valid reviewed return may issue an immutable SCR0.00 stock-only
  credit note when cumulative currency rounding assigns no cent to that slice;
  stock quarantine, cost restoration and case consumption still occur.
- Stable operation IDs, transactional outbox events, tenant scoping, private/no-
  store reads and paginated invoice return/credit-note histories.
- Narrow View_Sale posted-invoice lookup by exact draft revision, so return-only
  staff do not need Post_Sale or receive checkout configuration/account mappings.
- No refund, credit redemption, replacement entitlement or direct sellable-stock
  reclassification is introduced.
