T19A reviewed return-stock condition transition — implementation evidence
Date: 2026-10-05

Bounded scope
- An exact processed T18 credit-note line may request an independently reviewed,
  non-serial QUARANTINED to DAMAGED transition.
- The transition preserves on-hand, reserved, available, valuation, reservations,
  pricing and accounting. It cannot create sellable stock or reuse a return source.
- Display saleability, disclosure and discounts, supplier claims, write-offs and
  loss accounting remain outside this slice and fail closed.

Implementation
- Tenant-scoped paginated source and manager-case reads expose server-derived return,
  handover, branch, location, product, batch and quantity lineage.
- Stable operation IDs, expected stock versions, runtime branch authority and the
  shared T04 request/review/consume lifecycle protect execution and replay.
- CONDITION movements preserve quantity while shifting the exact approved amount
  from quarantine to damaged. The execution result declares no valuation,
  accounting or pricing effect.
- The replay-safe migration installs the movement constraint, exact T18 lineage,
  approval/use, posting-receipt, cumulative-cap and current-balance database guard.
- Fresh metadata creation installs the same cross-ledger guard only after the final
  T18 source table exists; application startup registers schema, permissions and
  the four private API paths.
